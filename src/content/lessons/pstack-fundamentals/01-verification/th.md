บทเรียนนี้เป็นบทสรุปชุมชนโดย SuperChoice AI ไม่ได้เกี่ยวข้องหรือได้รับการรับรองจาก Cursor, xAI หรือ Lauren Tan เรียงความต้นฉบับเป็นของเธอ: [ภาค 1](https://x.com/poteto/status/2094457600259842065) ตอนเขียนคอร์สนี้ หน้านั้นตอบ HTTP 403 ดังนั้นบทเรียนจึงเป็นร้อยแก้วต้นฉบับจากรีโพซิทอรี pstack และจากสำเนาสาธารณะของเรียงความ มันไม่ใช่ถอดความ อ่านของเธอเมื่อเข้าได้

ในเรียงความเธอเขียนว่าวิธีทำงานนี้ทำให้เธอลงพูลรีเควสต์ในระดับ 2,000 รายการในหนึ่งเดือน ตัวเลขนั้นเป็นรายงานของเธอ คอร์สนี้ไม่ได้ตรวจสอบ มัน สิ่งที่คอร์สจะขอให้จำคือกลไก ไม่ใช่ตัวเลข

## ปิดลูป

verification ในคอร์สนี้หมายถึงเอเจนต์บอกได้ว่างานเสร็จหรือยังโดยตรวจงานจริง มันรันฟีเจอร์ อ่านค่า ดูภาพหน้าจอหรือร่องรอย แล้วไปต่อจนกว่าการตรวจจะผ่าน ถ้าทำไม่ได้ คุณยังเป็นคอขวด เอเจนต์ที่มากขึ้นจึงหมายถึงงานที่คุณต้องรีวิวด้วยมือมากขึ้น

เธอมอง verification skill ที่ดีเป็นโครงสร้างพื้นฐาน ถนนที่ราดแล้วขยายทุกคนที่ใช้ รวมถึงคนที่ไม่ได้เขียนโค้ด พรอมต์ฉลาดที่อยู่ในแชทเดียวไม่ทำอย่างนั้น ปลั๊กอินกล่าวความคิดเดียวกันเป็นหลัก prove-it-works: อย่าประกาศความสำเร็จเพราะโปรเจกต์คอมไพล์ได้ หรือเพราะคำตอบฟังดูมั่นใจ

## สร้างสกิลจากรีโพ

`/create-verification-skill` สัมภาษณ์รีโพซิทอรี มันหาว่าผู้ใช้แตะอะไร แอปเริ่มอย่างไร อะไรขับมันได้ (สายรัดที่มีอยู่แล้ว ไม่งั้นก็เบราว์เซอร์ เทอร์มินัล หรือ HTTP ธรรมดา) และหลักฐานแบบใดจะพิสูจน์พฤติกรรม มันถามคุณเฉพาะสิ่งที่โค้ดตอบไม่ได้

สกิลที่มันเขียนมีผู้อ่านเป็นเอเจนต์ ส่วนที่ต้องจำคือ Launch, Doctor, Drive, Evidence และ Cleanup พร้อม feature map ในไดเรกทอรี features ก่อนส่งมอบ ตัวสร้างต้องพิสูจน์สกิลหนึ่งรอบ: เปิดแอป รันการตรวจสุขภาพ ขับหนึ่งฟีเจอร์ เก็บหลักฐาน เก็บกวาด แล้วยืนยันว่าหลักฐานยังอยู่ ถ้าการซ้อมนั้นล้มเหลว อย่าใช้ผลลัพธ์

เธอยังส่ง Dr Eggbot มากับ pstack เป็นบอทสำหรับสร้างบอท ทางหนึ่งที่เธออธิบายคือขอให้บอทนั้นสร้างบอทวิศวกร แล้วให้บอทวิศวกรรัน `/create-verification-skill` และจัดตาราง `/maintain-verification-skill` คุณไม่จำเป็นต้องใช้ทางนั้น คำสั่งเองคือส่วนที่ข้อสอบสนใจ

## Feature Map

เอเจนต์หลงเมื่อผลิตภัณฑ์มีประตูมากกว่าที่พรอมต์จะไล่ได้ Feature Map คือดัชนีกะทัดรัดที่เขียนจากฝั่งผู้ใช้ ตัวอย่างในปลั๊กอินเข้มงวดเรื่องรูปทรง ไฟล์ฟีเจอร์เปิดด้วยชื่อเรื่องและย่อหน้าของพฤติกรรมที่ผู้ใช้เห็น แล้วตามด้วย H2 สี่ส่วนพอดี

- Sub-features รหัสสั้นพร้อมหนึ่งบรรทัด
- How to get to it (user POV) ทุกทางเข้าที่คนมี
- Driving it with คำสั่งควบคุม เงื่อนไขก่อน แล้วคู่การกระทำของผู้ใช้กับคำสั่งที่ตรงตัวและผลที่สังเกตได้
- Gotchas กับดักที่ทำให้การรันเสียเปล่า

อย่าใส่รายละเอียดการอิมพลีเมนต์ แผนที่ระบุทาง ที่จับ สถานะที่ต้องมี คำสั่ง และหลักฐาน

เธอเรียกสิ่งนี้ว่าความจำที่ทำให้เป็นรูปธรรม ความจำในแชทและที่เก็บเวกเตอร์เก่าในแบบที่มองยาก โค้ดเบสคือบันทึกของสิ่งที่ทีมตัดสินไปแล้ว แผนที่คือภาพย่อของบันทึกนั้น เล็กพอที่จะใช้โทเคน เพราะมันอยู่ในสกิล ผู้ร่วมทำทุกคนใช้ร่วมกัน

`/maintain-verification-skill` คืองานบำรุง รันอย่างน้อยทุกวัน สกิลบำรุงอ่านแต่ละฟีเจอร์จากซอร์ส ขับแต่ละฟีเจอร์ที่ถูกทำแผนที่หนึ่งครั้ง แล้วจบด้วยหนึ่งในสามผล: สะอาด พูลรีเควสต์เดียวของการแก้ไขในไดเรกทอรีสกิล หรือถูกบล็อก มันไม่แก้โค้ดผลิตภัณฑ์เพื่อซ่อนการถดถอย ถ้าการขับสดเจอบั๊กของผลิตภัณฑ์ มันรายงานบั๊ก

## CLI ควบคุม

"สร้างคันโยก" หมายถึงให้เครื่องมือแก่เอเจนต์แทนย่อหน้า สำหรับการตรวจงาน เครื่องมือคือ CLI เล็ก ๆ เอเจนต์เลิกเขียนสคริปต์คลิกที่ใช้แล้วทิ้ง และการรันทุกครั้งเป็นการรันเดียวกัน คุณสมบัติที่เธอต้องการ:

- คำสั่งไม่กี่คำที่แต่ละคำทำงานจริง
- `--dry-run` ในสิ่งที่ทำลายข้อมูล
- คำสั่งย่อย เพื่อให้พื้นผิวค่อย ๆ ปรากฏ
- ข้อผิดพลาดที่บอกว่าควรทำอะไรแทน
- ผลลัพธ์ที่เครื่องอ่านได้ เช่น JSON

ใช้เวลาทำให้ CLI นั้นน่าเบื่อและถูกต้องก่อนเพิ่มความฉลาด และทำให้สภาพแวดล้อมพัฒนาทำซ้ำได้: ข้อมูลตั้งต้น ผู้ใช้ทดสอบ คำสั่งเดียวที่ยกสแตกขึ้นแบบเดิม สกิลตรวจงานที่ขึ้นกับอารมณ์ของแล็ปท็อปไม่ใช่โครงสร้างพื้นฐาน

## เอเจนต์รันที่ไหน

หลังจากพูลรีเควสต์สองสามรายการลงด้วยวิธีนี้ สิ่งล่อใจคือการขนานด้วย git worktree บนเครื่อง ข้อโต้แย้งภาค 1 ของเธอคืออย่าใช้ทางนั้นเป็นแผนหลัก worktree กินดิสก์และชนเพดานที่เครื่องที่คุณนั่งอยู่ cloud agent ของ Cursor รันบนคอมพิวเตอร์ระยะไกลที่ติดตั้งดีเพนเดนซี เปิดแอป และบันทึกวิดีโอได้ การสร้างสภาพแวดล้อมครั้งแรกสแนปช็อตได้เพื่อให้รันถัดไปเริ่มเร็ว ความขนานเป็นผลของการตรวจงาน ไม่ใช่สิ่งที่ใช้แทนมัน

## เรียกใช้อย่างไร

เริ่มงานด้วย `/poteto-mode` และระบุ verification skill เมื่อคุณต้องการหลักฐานแบบเฉพาะ พรอมต์ฟีเจอร์ขอวิดีโอกับภาพหน้าจอ พรอมต์บั๊กขอให้เอเจนต์ทำซ้ำบนสาขาหลักก่อน แล้วแก้ แล้วโชว์วิดีโอ พรอมต์ประสิทธิภาพขอร่องรอยของสภาพเดิมก่อนแก้ใด ๆ แล้วตรวจว่าชัยชนะเป็นจริง

บน Cursor การเลือกสกิลจากเมนูสแลชแล้วกด Option+Enter (Alt+Enter บน Windows) ปักมันเป็นโหมดกำหนดเอง การกด Enter ธรรมดาแนบมันกับข้อความเดียว

การติดตั้งตาม README คือ `/add-plugin pstack` บน Cursor

## สิ่งที่ข้อสอบจะถือว่าคุณพูดได้

คุณควรพูดได้ว่า verification มีไว้ทำอะไร บอกชื่อส่วนของสกิลที่ถูกสร้าง บอกชื่อหัวข้อสี่ส่วนของไฟล์ฟีเจอร์ บอกคุณสมบัติของ CLI และแยก Feature Map ออกจากแผนผังเว็บหรือที่เก็บเวกเตอร์ คุณควรพูดได้โดยไม่เลี่ยงว่าโปรไฟล์สาธารณะของ Lauren Tan คือ xAI และ React Compiler ว่า README เล่า Meta, Netflix และ Cursor และว่าเธอไม่ได้ทำงานที่ Tesla
